# R-035 blinded reviewer trial kit

This kit is **not** the frozen release benchmark. Cases A and B were generated for this trial only by `build_trial.py`, which uses the independent fixture builder's reporting arithmetic and mapping, never `src/`. They have fictional names and LEIs. The builder creates both normalized input packages. The plain Excel diffs and scoring books are generated by `build_sheets.mjs`; the two tool outputs were produced by the local CLI. Keep `coordinator/` away from reviewers.

`SHA256SUMS` fixes the 17 current input, output, answer-key and scoring-template files before recruitment. From `tests/trial/`, verify them with `shasum -a 256 -c SHA256SUMS`. Record any authorized revision and its new checksum before a reviewer opens a case. The coordinator keeps the blank scoring template as the reference copy and writes observed results into a separate working copy.

## Materials and trial method

For each case, distribute the same `opening.xlsx` and `closing.xlsx` to both methods. For the Excel method, add only `plain-excel-diff.xlsx`. For the tool method, add only `tool/reconciliation.xlsx` and `tool/summary.json`. Do not provide the challenge pack: the current deterministic JSON lacks the validation and abstention fields required to release one, and an API key is not available. Do not provide PNG previews, build scripts, `build-data/`, or the other method's output. Give every reviewer the same `reviewer-task.md`.

The coordinator assigns two practising life actuaries to each of the four sequences in `coordinator/assignment.xlsx`. Each reviewer sees A and B once each, with one case under each method. The timing clock starts when the case materials are opened and stops when the reviewer submits their **first written issue list**. Give no feedback between runs. The reviewer must work alone and may not consult the answer key. Record start and submission timestamps at the time of the event; do not estimate them later.

## Matching difficulty

Both packages use the same two annual dates, solo supervisory 2.8.2 variant, EUR scale and precision, Standard Formula method, and exactly 608 populated normalized coordinates in each period. Each has exactly two seeded issues: one S.23.01 versus S.25.01 total SCR discrepancy of EUR 6 million, and one change from no VA to applied VA with a EUR 5 million S.22.01 impact movement. A has the SCR break at closing; B has it at opening. The generated financial levels and fictional entity differ, so the answer is not a copied worksheet. The defect classes, number of clues, magnitude and source templates match. The answer key shows the independent arithmetic. The cases are matched by design, not proven equal in human difficulty; the balanced crossover helps control that uncertainty.

## Blinding and scoring

The coordinator renames each submitted issue list with the blind run ID from `assignment.xlsx` and removes reviewer names, method labels and output-file references before handing it to the scorer. The scorer receives only anonymized findings, `coordinator/answer-key.md`, and `coordinator/blind-adjudication.xlsx`; they enter 0 or 1 for each defect class and blind run. The scorer never sees the assignment or timing workbook. Once all 32 class opportunities are adjudicated, the coordinator copies those counts into the **Blind adjudication** sheet of `coordinator/timing-and-scoring.xlsx`, reveals the method for each blind ID in **Detection rates**, enters the two methods and actual timestamps in **Times**, and reviews the formulas. Use the same 0/1 rule for both methods; duplicate descriptions of one defect count once.

The workbook computes each reviewer’s `(Excel minutes − tool minutes) / Excel minutes`, the median of eight against 35%, and the separate correct/available rate for cross-template and comparability defects under each method. A completed gate needs all eight paired times and all 32 blinded classifications; the tool must equal or exceed Excel for each class. The owner signs the observed times, counts and outcome in `coordinator/SIGNOFF.md`. Until then R-035 is open.

The two CLI commands used to prepare tool materials were:

```text
PYTHONPATH=src .venv/bin/python -m s2movement compare tests/trial/materials/A/opening.xlsx tests/trial/materials/A/closing.xlsx --output-dir tests/trial/materials/A/tool
PYTHONPATH=src .venv/bin/python -m s2movement compare tests/trial/materials/B/opening.xlsx tests/trial/materials/B/closing.xlsx --output-dir tests/trial/materials/B/tool
```

Both produced a workbook and JSON and exited 1 because the deliberately seeded cross-template reconciliation failed. That is expected for these trial materials.
